Cap the blast radius.

Anthropic published its containment playbook for Claude. Three patterns, matched to the user's ability to evaluate a bash command. The takeaway for anyone shipping agents: probabilistic defences inside the model are not enough — isolation has to live in the runtime, and the part you wrote is probably the weakest piece.

claude.ai

Ephemeral gVisor containers on isolated servers.

Minimal blast radius. Limited capabilities. Anyone, anywhere.

OS-level sandbox with human-in-the-loop approvals.

For developers who can read a shell command before it runs.

Sealed virtual machines, no host bleed.

Ephemeris · Issue 040 03 / 07 · OpenAI
Case study · Self-improving agents

Filing season as the training set.

A joint deployment with Thrive and Crete, written up by OpenAI · Codex with GPT-5.5 · 27 May 2026.

The pitch: tax filings are exactly the workload an agent should win at, because every form is a long checklist with deterministic ground truth and a sharp annual deadline that produces fresh labelled data the moment a return is accepted by the IRS.

The interesting part is not that an agent files; it is that the agent improves from filing. The team treats each accepted return as an eval row and the rejections as a debugging signal. The error cases feed back into the prompt library, the tool wrappers, and the next month's evaluation harness, with Codex doing the modifications itself under review.

If you are building a vertical agent, the structural lesson is to design the surrounding pipeline so the task's own outputs become the next iteration's tests. Tax happens to ship them on a calendar.

"Substantive feedback in minutes instead of hours" was the line OpenAI used about Ramp last week. This one is harder: substantive feedback that updates the agent itself.

You do not need to pick one.

A persistent question gets a clean answer: keep your backend OpenTelemetry collector, drop Sentry's SDK on the frontend, and let OTLP do the bridging. The trace-continuation step is the part to read carefully — it's what makes a click in the browser the parent of an OTel span on the server.

FrontendSentry SDK · captures user actions, errors, performance · emits trace context
TransportOTLP — direct to Sentry's endpoint, or via an OpenTelemetry Collector for fan-out
BackendExisting OTel instrumentation kept as-is · spans inherit the browser-side parent
OutputOne distributed trace · frontend errors, backend spans, logs · single timeline

Ephemeris · Issue 040 06 / 07 · via @ProductsAndStartups
Security · Red-teaming

Hostage-taking still works on agents.

A roundup of recent adversarial research, surfaced through the channel: AI agents continue to fold under absurd framings — fictional treaties, ransom letters, fabricated authority — because language is polysemous and instructions are not capabilities. The fixes are architectural.

01

Scope capabilities

The agent should not be able to do the dangerous thing — full stop. No clever prompt can lift a tool it doesn't have.

02

Isolate credentials

One identity per task, expired on completion. Long-lived tokens are how hostage scenarios become billing events.

03

Treat the prompt as untrusted input

Including everything the agent reads downstream — pages, files, tool outputs. Especially those.

04

Skip "do not"

Instructions describe; permissions enforce. Build the second one. The first is documentation.

Ephemeris · Issue 040 07 / 07 · via @ProductsAndStartups
Playbook · Agent harness

Stop writing code. Start writing checks.

A useful distillation of takeaways from the Code with Claude conference, reposted through the channel. The thesis: the moat moves out of the source tree and into the harness — verification, evaluation, memory, the small infrastructure that lets a cheap model do an expensive thing.

1.
Pair a cheap model with an expensive advisor. Reserve the smart one for the moments that matter; let it review, not write.
2.
Shift engineering effort into verification — tests, evals, sandboxes. The thing the model can't fake.
3.
Auto-delete code that next month's model will make redundant. Treat the codebase as the cache, not the asset.
4.
Invest in agent memory: durable, queryable, project-scoped. Context is now the bottleneck, not capability.
5.
Optimise for verifiable side effects, not generated tokens. Counting tokens is back to counting punch cards.
6.
Treat your IDE as a workbench for many agents, not a chat window for one. Parallel runs change everything.
7.
Sell the harness, not the wrapper. Anyone can wrap an API; few will build the surrounding plant.
