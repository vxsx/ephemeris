Your standards are prose. The reviewer needs JSON.

Cloudflare writes its engineering standards as RFCs — anyone can open one, it takes rounds of review, a domain owner signs off. The part worth stealing is what happens next: the prose is compiled into JSON statements tagged MUST or SHOULD, each with a stable slug, so a review agent pulls the four rules that apply to a diff instead of dragging the whole corpus through its context window.

250K violations flagged by the AI code reviewer since early 2026
16K merges blocked outright for breaking a MUST
600 unique specs reviewed, across 3,200+ invocations
RFC merged Approved → findings only Enforced → blocks the merge

Ephemeris · Issue 106 02 / 05 · Cloudflare
Dev tools · Observability

The trace is on your laptop before you deploy

Update Wrangler and wrangler dev starts emitting OpenTelemetry spans for fetches, handler lifecycles and every binding call — KV, R2, D1, Durable Objects, Queues — captured by workerd itself. The dev server notices when a coding agent is attached and prints a query endpoint, so the agent reads the failing span and the correlated console logs instead of asking you to paste them.

$ wrangler dev

Ephemeris · Issue 106 03 / 05 · GitHub
Agentic coding · Automation

Leave a comment. The agent picks it up.

Copilot cloud agent automations can now fire on an issue or pull-request comment, matching text you choose. The trigger is the cheap part — what it buys is a place to park the jobs nobody schedules: regenerate the docs a diff invalidated, go read the error log attached to a bug, open the refactor ticket someone promised to file.

Repository → Agents → Automations

your trigger text → what the cloud agent runs
“update the docs” → generate or refresh documentation from the code change
“investigate this” → work through the error logs behind the issue
“queue a follow-up” → open the refactor or tech-debt task

On Copilot Pro, Pro+, Max, Business and Enterprise. Business and Enterprise need an administrator to switch on the cloud agent policy first.

Ephemeris · Issue 106 04 / 05 · GitHub
Security · Code scanning

One config file, every repository you own

CodeQL default setup was the version you took when you did not want to maintain a workflow file in every repository. A new repository property, github-codeql-config-file, points default setup at a config of yours and merges it with the built-in one — extra queries, excluded paths, a chosen threat model — set as an organisation-wide default and overridden per repo where it matters.

property  github-codeql-config-file
