Agent infrastructure · Browsers

Chromium spent 1,173 milliseconds. This one spent 380.

Cloudflare rebuilt the browser as a Workers application. Kitesurf runs pages through the Rust engines Blitz and Stylo instead of Chromium, with each page an ephemeral Worker and all egress funnelled through one sandboxed outbound proxy. It speaks Chrome DevTools Protocol, so Puppeteer and Playwright connect unchanged — add browser=kitesurf and your existing scraper points at it.

Ephemeris · Issue 107 02 / 05 · Cloudflare
Web standards · MCP

Flip a switch and your site answers in tools

WebMCP is the browser-side counterpart to MCP, experimental in Chrome 146 and exposed to pages as document.modelContext. A browser agent asks the page what it can do rather than guessing which button to click. Cloudflare's developer preview injects the bridge with HTMLRewriter at the edge, so a site opts in from the dashboard without shipping code or touching its origin.

Before

The agent screenshots your page, guesses at the DOM, and clicks coordinates that move next release.

After

The page registers named tools. The agent calls them and reads a typed result back.

<script src="/.webmcp/bridge.js" data-mcp-url="/mcp"></script>

Ephemeris · Issue 107 03 / 05 · Vercel
Tooling · Open specification

One folder your skill ships in. Five clients read it.

Agent Plugins is a vendor-neutral packaging format, published at 1.0.0 with the schema and conformance checklists on agent-plugins.org. A plugin is a manifest plus two component types — Agent Skills and MCP servers — and clients handle their own distribution. If you maintain an internal skill that four teams have each copied into a different editor's config, this is the shape to move it to.

my-plugin/
├── plugin.json  # spec version + name
├── skills/
│   └── review/SKILL.md
├── mcp.json    # server config
└── .codex/     # optional, namespaced

Reads it at launch

Ephemeris · Issue 107 04 / 05 · Sentry
Case study · Automation

Seer opens the pull request. Claude finds who should read it.

Sentry's own fix pipeline had a gap at the end: Seer diagnosed production errors and opened PRs, and the PRs sat there. The fix is an hourly Claude routine that sweeps PRs opened in the last four hours, asks Seer who owns the code by commit history, and tags that person with context. Six weeks of numbers are in the post, including the one that looks bad and isn't.

$ routine run --every 1h --window 4h
→ seer.autofix opened 3 PRs
→ resolve reviewer from commit history
→ tag + post context to #seer-prs
since mid-July 2026
action rate on PRs +21%
48-hour response rate +13%
closed without merge +12.5% ← duplicates and better fixes, not misses

Dev tools · Review loop

Edit the file. The agent reads your margins.

Peter Yang's human-review opens the HTML or Markdown your agent produced in a local browser view where you type directly into the text and leave Google-Docs-style comments, then sends the whole batch back at once. It replaces the round of chat messages where you describe an edit instead of making it. MIT, runs locally, no account or API key; first commit 27 July, 512 stars since.
